# VisionCraft V1 录屏演示脚本

面向「录屏成片」形态的演示稿。三段各有一条固定样本，照着点就行；每段都写明
**看什么、说什么、证据在哪**。

样本由 `tools/prepare_p6_demo_samples.py` 幂等准备，只创建 `p6demo_*` 项目，
从不触碰 `project_*` 用户数据。准备与演示**全程零外发**。

---

## 1. 开录之前

```powershell
cd D:\Agent\summercompetition\StoryCraft\VisionCraft

# 1) 准备三个固定样本（可重复执行，会重置同名样本）
.venv\Scripts\python.exe tools\prepare_p6_demo_samples.py

# 2) 起本地服务
.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000

# 3) 打开 http://127.0.0.1:8000
```

浏览器建议 1440×900 以上、关掉无关标签页与通知。录屏前先跑一次
`tools/test_p6_demo_samples.py`，确认三个样本齐备（39 项断言全绿）。

样本一览：

| 项目 | 标题 | 演示什么 |
|---|---|---|
| `p6demo_story` | P6 演示 A · 短文本完整闭环 | 短文本 → 改编 → 分镜 → 真实镜头 → 合成成片 |
| `p6demo_compare` | P6 演示 B · 同镜头多模型对比 | 同一镜头同一提示词，三家视频模型的真实差异 |
| `p6demo_recovery` | P6 演示 C · 失败恢复案例 | 云端任务丢失后的失败呈现与处置入口 |

界面阶段导航（右侧）依次是：文本理解 / 故事线选择 / Story Bible / 分镜设计 /
关键帧 / 镜头视频 / 成片合成 / 导出与交付。

**总时长建议 9～11 分钟**：A 段 4 分钟、B 段 3 分钟、C 段 2 分钟，留 1～2 分钟收尾。

## 2. 第一段 · 短文本完整闭环（`p6demo_story`）

**要讲的一件事：** 一段几百字的短文本，怎么变成一条 20 秒的可播放成片，
而且中间每一步都可审核、可回退。

| # | 操作 | 讲解要点 | 证据 |
|---|---|---|---|
| 1 | 左侧选中「P6 演示 A · 短文本完整闭环」 | 先说素材来源：这是**真实付费生成**的 4 个镜头，不是彩条夹具 | 摘要区显示 1280x720、16:9 |
| 2 | 打开「文本理解」 | 原文 → 改编方案 → 已确认的方案；点开可看到候选方案与采用理由 | 方案卡片 |
| 3 | 打开「Story Bible」 | 人物、场景、服装被固化成约束；**后续每个镜头提示词都从这里取**，这是跨镜头一致性的来源 | 角色表 / 场景表 |
| 4 | 打开「分镜设计」 | 4 个镜头，每个都有叙事目的、动作、镜头运动 | 分镜列表 |
| 5 | 打开「关键帧」 | 首帧是 I2V 的输入锚点 | 关键帧缩略图 |
| 6 | 打开「镜头视频」 | 逐镜播放。**这里要强调：这 4 段是 2026-08-28 火山方舟 `doubao-seedance-2-0-260128` 的真实输出**，每段约 5.09 秒 | 镜头视频播放器 |
| 7 | 打开「成片合成」 | 展示合成配置（分辨率、字幕、保留原声），点合成或直接播放已有成片 | 成片预览 |
| 8 | 打开「导出与交付」 | 成片可下载；改规格会让成片标记过期并提示重合成 | 下载按钮 / 过期提示 |

**结尾一句：** 「这一条从文本到成片，中间没有任何一步是人工剪的；镜头是模型生成的，
拼接、混音、烧字幕都是本地 FFmpeg 按固定规格做的。」

**成片规格基准（已在回归里断言）：** 1280×720、约 20.35 秒、带 AAC 音轨。

## 3. 第二段 · 同镜头多模型对比（`p6demo_compare`）

**要讲的一件事：** 同一个镜头、**同一句提示词、同一张首帧**，交给三家视频模型，
出来的东西不一样——所以「镜头级模型选择」不是一个花哨功能，而是必需品。

| # | 操作 | 讲解要点 | 证据 |
|---|---|---|---|
| 1 | 左侧选中「P6 演示 B · 同镜头多模型对比」 | 先声明前提：提示词与首帧**完全一致**，这一点是可验证的 | 首帧缩略图 |
| 2 | 打开「镜头视频」 | 该镜头下挂着 3 个版本，分别来自三家 | 版本历史列表 |
| 3 | 依次播放三版 | 边放边报参数差异 | 见下表 |
| 4 | 切到「关键帧」 | 指认三家共用同一张首帧 | 同一张图 |
| 5 | 收尾 | 「同一句提示词，三家给出的分辨率、时长、动态都不一样。工作台必须允许逐镜头选模型，也必须把每次输出的真实规格记下来。」 | 版本记录里的 change_summary |

**三家真实输出（同一提示词、同一首帧，2026-08-28 各调用一次）：**

| 版本 | Provider | 模型 | 请求参数 | 实际输出 | 文件 |
|---|---|---|---|---|---|
| v1 | ark | `doubao-seedance-2-0-260128` | 720p / 5s / 16:9 | **1280×720，5.09s** | 3.2 MB |
| v2 | dashscope | `wan2.7-i2v` | 720P / 2s | **1110×828，2.02s** | 1.4 MB |
| v3 | minimax | `MiniMax-H3` | 768P / 4s | **1024×768，4.46s** | 0.9 MB |

三家输出规格互不相同，这一条在回归里是断言，不是印象
（`tools/test_p6_demo_samples.py` 的「三家输出规格各不相同」）。

**对比图（可直接放进录屏或作为讲解配图）：**

```powershell
.venv\Scripts\python.exe tools\make_p6_compare_sheet.py
# 产出 output/playwright/p6demo/compare-three-providers.png
```

三家各抽第 1 秒的一帧横向拼接，图上带 `ark 1280x720` / `dashscope 1110x828` /
`minimax 1024x768` 标签。一眼能看出：构图远近、人物在画面里的比例、蛊虫与光雨的
位置都不一样——**同一句提示词，三家给的不是同一个镜头**。

> 提问预案：**为什么 dashscope 是 1110×828？**
> 因为视频模型的实际输出规格由模型自己决定，不完全服从请求参数。工作台把
> 「请求的」和「实测的」分开记录，合成前再统一到项目规格——这也正是 P6-A
> 要拒绝「占位视频与失效视频」的原因。

## 4. 第三段 · 失败恢复案例（`p6demo_recovery`）

**要讲的一件事：** 视频生成会失败，而且有一种失败特别阴——**任务在云端消失了**。
工作台要能识别、能停住、能给人一个可执行的下一步。

| # | 操作 | 讲解要点 | 证据 |
|---|---|---|---|
| 1 | 左侧选中「P6 演示 C · 失败恢复案例」 | 说明这是一次**真实失败**的记录，错误原文一字未改 | — |
| 2 | 打开「镜头视频」 | 该镜头状态是失败，诊断区给出中文说明与处置建议 | 失败诊断卡片 |
| 3 | 点开失败详情 | 展示平台返回的原文 | 见下 |
| 4 | 指出诊断按钮 | 「安全改写并重试」——它会读取失败任务的错误上下文，据此改写提示词再建新版本 | 按钮 |
| 5 | 收尾 | 「失败不是静默的：任务中心有记录，镜头状态是失败的，下游镜头不会被盲目继续提交。」 | 任务中心 |

**失败原文（逐字取自 2026-08-31 的真实调用）：**

```
error_code    : TASK_ID_INVALID
cloud_status  : invalid_task_id
error_message : MiniMax query returned HTTP 400 invalid task_id (2013);
                task no longer exists platform-side,
                request_id 06fe8f6d03411586041c21721c59fc1a
```

**这一段要如实说明的三件事：**

1. 失败记录是**真实的**（2026-08-31 对 `MiniMax-H3` 的一次真实付费调用）。
2. 该次失败在编排层的行为也是真实的：回查后判定失败，**其余镜头被标记
   `stopped_by_failed_shot` 并停止提交**，整体状态 `stopped_after_refresh`。
   完整证据见 `output/playwright/archive-2026-09-20-failed-2shot/resume_report.json`。
3. **演示时点「安全改写并重试」走的是 mock Provider，因此不产生费用。**
   如果要用真实 Provider 演示恢复成功，那是又一次付费调用，需要单独授权
   （见第 6 节）。

## 5. 收尾（约 1 分钟）

按三条样本各回一句：

1. **闭环**——从一段文本到 20 秒成片，全程可审核、可回退、可重合成；
2. **对比**——同一镜头的三家真实输出规格互不相同，逐镜头选模型是刚需；
3. **恢复**——云端任务消失这类失败被明确识别并停住，人拿到的是可执行的下一步。

再补一句工作台之外的东西：**48+1 项无费用回归**跑在隔离数据目录里，
每次改动都在同一批固定样本上复验——上面三条样本本身也被回归覆盖。

## 6. 诚实性附注（录屏时不必逐条念，但被问到要答得上）

**哪些是真实付费产物：**

- A 段的 4 个镜头：2026-08-28 火山方舟 `doubao-seedance-2-0-260128`，真实调用；
- B 段的三家对比：2026-08-28 ark / dashscope / minimax 各一次，真实调用；
- C 段的失败记录：2026-08-31 `MiniMax-H3`，真实调用。

**哪些是本地生成、不是模型产出：**

- A 段的背景音（FFmpeg sine 波）与字幕（本地 SRT）——成片包装用，演示「本地音频/字幕」能力；
- A 段成片由**本地 FFmpeg** 合成，P6-C/D/E 的合成命令统一到 1280×720 / 24fps / yuv420p / libx264；
- 三个样本的改编步骤走**本地 mock 规划器**，不调用 LLM。

**哪些步骤如果照做会花钱：**

| 动作 | 费用 |
|---|---|
| 重新跑一次真实三家对比 | 约 2～3 元（参考：一次 2 镜 MiniMax 真实跑 ≈ 2.84 元） |
| 在 C 段用真实 Provider 演示「恢复成功」 | 一次视频调用（768P / 4s 级别） |
| 重新生成 A 段的 4 个镜头（ark 720p 5s×4） | 视方舟定价，约数十元量级 |

**授权口径：** 任何真实调用都需要事先拿到明确同意。当前约定是**单次消费不超过
20 元，且每次调用前先报清单**（Provider / 模型 / 镜头数 / 时长 / 分辨率 / 预计费用）。
