# VisionCraft 页面布局与阶段素材交互设计

> 本文是 VisionCraft V1 页面布局、阶段导航和素材交互的设计依据。界面实现、接口联调和浏览器验收应以本文的交互规则为准。视觉细节可以迭代，但不得改变本文定义的对象关系和状态语义。

## 1. 设计目标

VisionCraft 是“影视创作工作台 + AI 协作流程”，不是单纯的聊天页面。用户需要始终理解三件事：项目正在执行什么、当前正在查看什么、当前素材能做什么。

页面围绕三层对象组织：

```text
项目 → 制作阶段 → 阶段素材
```

同时保留实时任务中心，用于展示异步图片、视频和合成任务的实际进度。

## 2. 页面总体布局

桌面端采用三栏工作台，底部固定任务中心：

```text
左侧：项目与全局配置
中间：当前阶段工作区
右侧：完整制作流程导航
底部：全局任务中心
```

### 2.1 左侧：项目与配置

左侧负责项目级内容：

- 新建项目；
- 当前项目配置摘要或编辑表单；
- 项目列表；
- 项目名称、原文、视觉风格、比例、时长、镜头策略、自动/监制模式。

项目列表至少显示项目名称、当前阶段、最近更新时间、进度和异常标记。

### 2.2 中间：阶段工作区

中间区域只处理当前查看阶段，内容随阶段切换：

| 阶段 | 主要内容 |
|---|---|
| 文本理解 | 原文摘要、人物、场景、事件和引用 |
| 故事线选择 | 候选故事线、原文片段、推荐理由 |
| 改编方案 | 方案比较、目标时长和改编范围 |
| Story Bible | 角色卡、场景卡、视觉风格和约束 |
| 分镜设计 | 分镜列表、镜头顺序、动作和原文依据 |
| 关键帧制作 | 首帧、尾帧、参考图和重绘操作 |
| 镜头视频 | 视频预览、Provider、模型和任务进度 |
| 成片合成 | 镜头顺序、成片预览、合成和导出状态 |

阶段工作区支持两种素材视图：

- 缩略图视图：快速浏览当前阶段的全部素材；
- 单素材视图：查看预览、进度、来源、版本和编辑操作。

### 2.3 右侧：制作流程导航

右侧始终显示完整流程：

```text
文本理解 → 故事线选择 → 改编方案 → Story Bible → 分镜设计 → 关键帧 → 镜头视频 → 成片合成
```

所有阶段都显示。短文本不需要的阶段显示为“跳过”或“当前文本无需此步骤”，不可点击执行，但可以展示完整产品能力。

阶段节点状态包括：

- 未开始；
- 处理中；
- 等待审核；
- 已完成；
- 已修改；
- 已失效；
- 失败；
- 跳过。

点击阶段只改变当前查看阶段，不自动运行任务。

## 3. 三种状态必须分离

前端不能把下列概念合并：

```text
executionStage：项目实际执行到的阶段
viewStage：用户当前查看的阶段
selectedAsset：用户当前选中的素材
```

例如项目正在生成视频时，用户仍然可以查看或编辑 Story Bible。此时右侧显示“镜头视频处理中”，中间显示 Story Bible，不能把项目执行状态误判为回退。

## 4. 新建项目与创建项目

两个操作必须分开：

### 新建项目

“新建项目”只打开空白表单，不创建数据库记录，也不影响当前项目。表单恢复默认值，用户可以填写新的项目配置。

### 创建项目

“创建项目”提交当前表单并创建真实项目。创建成功后：

1. 项目加入项目列表；
2. 自动选中新项目；
3. 左侧显示新项目实际配置；
4. 中间进入新项目初始状态；
5. 右侧显示该项目的阶段流程。

查看已有项目时，左侧显示配置摘要，并提供“编辑项目设置”。不应让用户误以为正在修改新项目。

## 5. 阶段查看、编辑与重做

已完成阶段允许查看。用户点击素材后，中间下方显示详情和编辑区。

编辑区的重做按钮遵循脏状态：

```text
没有实际修改：从此处重做并继续（禁用）
存在实际修改：从此处重做并继续（可用）
```

点击“从此处重做并继续”时，系统应：

1. 自动保存当前草稿；
2. 冻结新的阶段输入版本；
3. 使当前阶段之后的有效产物失效；
4. 从当前阶段重新执行；
5. 按自动模式或监制模式继续推进；
6. 通过任务中心显示实时进度。

如果用户离开存在未保存修改的阶段，应提供保存、放弃修改和取消离开三个选择。

## 6. 上游修改与下游失效

上游内容变化后，后续产物不能继续作为当前有效链路使用。

例如修改 Story Bible：

```text
Story Bible 修改
  ↓
分镜、关键帧、视频、成片从当前工作区失效
  ↓
重新生成分镜
  ↓
审核并继续生成后续内容
```

“清除下游”指清除当前有效工作区中的下游结果，不建议物理删除数据库历史。旧版本保留在版本历史中，并标记为 `invalidated` 或 `archived`；新任务只能引用新的有效版本。

页面默认只展示当前有效链路，历史面板才展示旧版本及其失效原因，避免新旧素材重叠和错误引用。

## 7. 自动模式与监制模式

### 自动模式

阶段完成后自动进入下一阶段。用户可以随时暂停：

```text
自动执行 → 用户暂停 → 编辑当前阶段 → 从此处重做并继续 → 恢复自动执行
```

### 监制模式

每个关键阶段完成后等待用户审核：

```text
生成完成 → 等待审核 → 修改/重做或采用 → 继续下一阶段
```

建议的操作名称：

- 采用并继续；
- 修改后重做；
- 暂停流程；
- 查看生成依据。

后端应区分普通暂停和用户编辑暂停，例如通过 `pause_reason`、`resume_from_stage` 表达原因和恢复位置。

## 8. 素材详情与血缘信息

选中素材后，详情面板至少展示：

- 所属项目和阶段；
- 所属镜头；
- 素材类型；
- 当前版本；
- 当前状态；
- 创建时间；
- Provider 与模型；
- 输入素材；
- 是否为当前采用版本；
- 是否允许传给下游。

例如视频应明确显示其首帧来自哪个关键帧版本。这样可以追溯“这段视频到底使用了哪张图”，并支持不同 Provider 组合的调试。

## 9. 任务中心

底部任务中心与右侧阶段导航职责不同：

- 阶段导航显示项目级流程；
- 任务中心显示具体异步任务。

任务中心默认收起，显示任务数量和当前摘要；展开后显示任务阶段、镜头、Provider、模型、进度、耗时、最近事件、失败原因和重试入口。

任务事件通过现有 SSE 和轮询机制实时更新：

- 排队和处理中立即显示；
- `waiting_remote` 明确显示“等待远端返回”；
- `asset.ready` 后自动更新对应素材；
- 失败后显示可执行的修改或重试操作；
- 不要求用户手动刷新浏览器。

## 10. 前端原型与真实联调

第一阶段可以先做纯前端交互原型，但模拟数据必须遵守真实后端合同：

- 使用已有状态枚举；
- 使用真实项目、阶段、素材、任务字段；
- 模拟自动模式和监制模式；
- 模拟任务进度和素材完成事件；
- 模拟上游修改造成的下游失效；
- 模拟新建项目、切换项目和恢复项目。

原型确认后再接入真实 API。前端应保持以下职责边界：

```text
api.js：请求接口
state.js：服务端状态、查看状态、编辑状态
workflowViewModel.js：后端状态到页面状态的统一映射
render.js：页面渲染
jobObserver.js：SSE、断线轮询和任务更新
```

## 11. 验收标准

### 页面与布局

- 三栏在 1440×900 和 1920×1080 下稳定显示；
- 长中文、模型名称、URL 不溢出；
- 素材预览比例稳定，不因任务状态变化跳动；
- 加载、空状态、失败和禁用状态清晰可辨；
- 中文内容无乱码，动态内容不会被错误转义。

### 核心交互

- 新建项目不会误修改当前项目；
- 创建项目后自动切换并显示正确配置；
- 点击阶段只切换查看内容，不误触发执行；
- 已完成阶段可以查看和编辑；
- 无修改时重做按钮禁用，有修改时启用；
- 上游重做后下游不再作为当前有效结果显示；
- 历史版本仍可追溯；
- 自动模式暂停后可以从当前阶段继续；
- 任务进度和新素材无需刷新即可显示。

### 数据与联调

- `executionStage`、`viewStage`、`selectedAsset` 分离；
- 任务事件只更新所属项目和素材；
- 切换项目后旧 SSE、轮询和迟到事件不能污染新项目；
- 新任务只引用当前有效版本；
- 所有修改均通过无费用测试和浏览器自动化验证。

## 12. 暂不纳入本阶段

- 移动端完整适配；
- 账户、权限和支付；
- 复杂聊天式智能体界面；
- 完整 P5-B 长文本 RAG；
- 付费 API 扩大测试矩阵；
- 大规模前端框架迁移。
